vjuu [vjuː]: "view", in rally English.

Don't open the file. Your agent already did.

Instead of telling you to "open X and review it", your agent runs vjuu X. A window opens with the markdown, diff or source. You comment on the lines, click Submit & continue, and your comments go straight back to the agent.

Install Source on GitHub

Install

Windows, macOS and Linux.

Uses the system web view: WebView2 on Windows, WKWebView on macOS, WebKitGTK 4.1 on Linux (Debian 12+, Ubuntu 22.04+).

Windows
winget install vjuu

Not yet: the winget package is waiting for Microsoft's approval. Until then, install it with cargo or from a .zip.

macOS
brew install kimvais/tap/vjuu

Not signed or notarised. Homebrew installs work as is; a binary downloaded by hand needs xattr -d com.apple.quarantine vjuu once.

Debian, Ubuntu
curl -fsSL https://vjuu.it/apt/vjuu.gpg | sudo tee /usr/share/keyrings/vjuu.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/vjuu.gpg] https://vjuu.it/apt stable main" | sudo tee /etc/apt/sources.list.d/vjuu.list
sudo apt update && sudo apt install vjuu
Anything else
cargo install --locked vjuu

Or a .zip, .tar.gz or .deb from GitHub Releases. Building on Linux needs libwebkit2gtk-4.1-dev and libgtk-3-dev.

Then, for Claude Code and Codex
vjuu setup

Installs the skill that tells your agents to run vjuu instead of asking you to open files. Run it again after an upgrade.

Why

Built out of annoyance.

By now I've mostly ditched my IDE for Claude Code in a plain terminal, one window split into 6 panes is just so much more convenient, and I no longer have to fight the terminal emulation quirks of IDE built-in terminals.

The catch: I asked Claude to count how many times it has told me to "open X and review it" since then.

79 times since mid-September. About 2.5 a day, and lately more like 5 (we've clearly grown closer). It also opened a markdown file for me unprompted 8 times, so roughly 1 in 10 it did the thing instead of delegating it back to the human. Very senior behaviour, honestly.

The "open X" part was the problem. Reviewing diffs in a terminal is miserable, and waiting for the IDE to start, then clicking around to get the side by side commit view, isn't much better. Plans were no fun either; no markdown editor does inline comments, and writing my comments inline into the source felt ... dirty. For a while my workaround was "push, open a PR and open the link in the browser", every single time, and then waiting for it to do the needful.

So I did the obvious thing and, without even googling whether it already exists (it probably does), built a tool & skill for it: vjuu opens a GitHub / GitLab style review view locally for diffs and markdown alike, I leave inline comments, and they go straight back to the calling session. Not googling first shows, sure ... but so does a review window that opens in well under a second.

Now Claude opens the thing itself and I just comment. Not counting how many times I've closed it with "No comments." already today (more than I'm willing to admit).

Bonus: it's keyboard first, everything has a keyboard shortcut (arrows to move, Enter to comment, Ctrl+Enter when done), and dark mode follows your system out of the box.

How it works

Fast enough to stay in the loop.

After the first window, vjuu keeps a pre-warmed one ready. A markdown file appears in about 15 ms. "Ai biliiv täts priti fääst."

  1. Open

    Anything the agent wrote.

    Markdown, diffs and patches, git diff ranges, any source file, or stdin. Several files stack in one window.

  2. Comment

    On a line or a selection.

    Click a line, or select across lines, paragraphs or diff rows. Keyboard first: arrows to move, Enter to comment, Ctrl+Enter when done.

  3. Return

    Markdown on stdout.

    The agent gets every comment with its file:line and the quoted lines. Each review is also saved, and vjuu last prints it again.

Themes

Fifteen themes, or your own.

GitHub, GitLab, Solarized, Gruvbox and Catppuccin, each light and dark, plus Graphite, Dracula, One Dark, Nord and Tokyo Night. Auto follows the system. A theme is a CSS file of colours: copy one, change it, and it shows up in the settings.
